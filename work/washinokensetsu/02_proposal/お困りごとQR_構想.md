# お困りごとQR 構想メモ

- 日付: 2026-10-22
- 出どころ: 小林の発案（会話）
- 状態: 課題整理（ラフモック前）
- 関連: `../03_documents/これからの仕事を考える会議_A4原稿.md`（お客様の困ったを聞く）

## 小林の案（事実）

1. お客さんの従業員がQRを読み込み、お困りごとを入力する
2. 入力はわしの建設だけが見られるリストに溜まる
3. 月末に、その内容をお客さんの社長に見せる
4. わしの建設で対応できるものは見積も出す

## 小林のまとめ（2026-10-23、Dropbox 小林写真/その他/アプリ開発資料 のWord。Claudeへの説明用）

- 名称案: お客様の会社の社員のお困りごとを社長や責任者に繋げるアプリ
- 社員: QRから入力画面にお悩みを入力（入力項目は検討中）／または記述用紙に書いて投函箱へ
- わしの建設: QR入力は自動でリスト化。用紙は月1回回収してリストへ手入力。自社で対応できそうなものは見積を作成。月1回、お客様の社長へリスト共有と見積提案
- お客様の社長: リストをもとに改善し、風通しの良い会社へ
- 現時点では、わしの建設がすべての入力を見る形

## 狙いの訂正（小林 2026-10-22）

- 建物の困りごとに限らない。給料など関係ない話も含めてよい
- 本来の目的は「社長と従業員をつなぐ」。社長が従業員の悩みを把握して解決する道具
- わしの建設は、その中で対応できるもの（建物・設備・作業場）の仕事をついでにもらう

## 狙い変更で出る論点（提案・採否は小林確認）

- 給料・人間関係・ハラスメントなどをわしが読むと、お客さん社員の信頼・秘密の扱いが重くなる。ハラスメントの相談窓口と混同される恐れもある
- 案: 入力時に分類を選ばせ、「建物・設備・作業場」はわしと社長、「それ以外」は社長だけが見る。わしは中身を見ない
- 匿名にするかどうかの重みが増す（悩みは匿名でないと書かれにくい）
- 同友会の「人を生かす経営」と相性が良く、同友会の仲間の会社にも広げやすい（推測）

## 何を解決するか（整理）

- 「困ってることは？」と聞いても「特にない」で終わる → 現場で働いている人が、その場で直接書ける
- 「ここ危ない」は働いていないと分からない → 働いている人から上がってくる
- 窓口の担当者を通さずに、社長に届く
- 月1回、決まった接点ができる（壊れてから呼ばれる → こちらから持っていく）

## 気になる点（反証）

- 社長の受け止め: 社内の不満が先に外の業者に届く形を嫌がる社長もいそう → 「社長の道具で、わしが代わりにまとめる」形にする必要
- 書かれる中身: 人間関係・給料など建物と関係ない話も来る → 入力画面で「建物・設備・作業場の困りごと」と絞る。社長に見せる前にわしが仕分ける
- 続くか: 書いても何も起きないと、すぐ書かれなくなる → 「受け付けました」「対応予定」を返す仕組みが要る
- わしの手間: 月末報告をお客さんごとに作るのは重い → 自動で一覧になる形にする
- 愛同工業は社内にお困りシートがある → 最初の相手は、そういう仕組みがない会社が向く
