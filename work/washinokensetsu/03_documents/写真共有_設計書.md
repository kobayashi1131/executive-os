## 1. 目的と範囲

**目的**：案件に付けた写真を、アプリを使う全員（社長・新井さん・小林さん）が、どの端末からでも見られるようにする。

| やる | やらない（後回し） |

| 各端末に残っている今の写真を新しい保存先に移す | 「写真」画面の仮の枚数表示を直す（今はランダムな数字） |
| 写真用GASを、後で改善提案にも使える形で作る | v2への写真機能の追加 |
| | 本番の案件スプレッドシートとGAS（社長アカウント）の変更 |

## 2. 全体の形

```txt
                    ┌─ 今のGAS（社長アカウント）── 案件スプレッドシート   ← 変更しない
アプリ（今の版） ───┤
                    └─ 写真用GAS（会社用アカウント）─┬─ Drive「WAC案件写真」フォルダ（写真の実体）
                                                      └─ 写真台帳シート（どの案件にどの写真があるか）
```

- 写真の実体と「どの案件にどの写真があるか」は、**どちらも会社用アカウントの側で持つ**。本番の案件シートに写真の列は足さない
  - 理由：今のGASはシートの列が決まっていて、知らない項目を送っても捨ててしまう（`api.js` のフォロー日のコメントで確認済み）。写真の列を足すには本番のGASを直す必要があり、A案の「本番に触らない」が崩れる
- 案件との紐づけには、案件の `id` を使う

## 3. 写真用GAS

### 3-1. 置き場所と設定

| 項目 | 内容 |
|---|---|
| アカウント | 会社用の新しいGoogleアカウント（無料Gmail） |
| プロジェクト名 | `wac-photos` |
| Driveのフォルダ | `WAC案件写真/{案件id}/` に1枚1ファイル。初回に自動で作る |
| 写真台帳 | 同じアカウントのスプレッドシート `WAC写真台帳`。初回に自動で作り、IDをスクリプトプロパティに控える |
| 合言葉 | スクリプトプロパティ `APP_SECRET` |
| デプロイ | ウェブアプリ。**実行ユーザー：自分（会社用アカウント）**、アクセスできるユーザー：全員 |

**デプロイの注意**：コードを直したら「デプロイを管理 → 編集 → 新しいバージョン」で更新する。「新しいデプロイ」を作るとURLが変わり、アプリから届かなくなる。

### 3-2. 写真台帳の列

| 列 | 中身 |
|---|---|
| fileId | DriveのファイルID |
| kind | `project`（今回はこれだけ。後で改善提案に使うときは `kaizen`） |
| ownerId | 案件のid |
| clientKey | 写真の中身から作った指紋（同じ写真の二重登録を防ぐ。4-3参照） |
| createdAt | 登録日時 |
| staff | 登録した人（端末に登録された担当者） |
| deleted | 削除したら `TRUE`（行は消さない） |

### 3-3. 受け付ける仕事

すべて POST。中身はJSONで、合言葉 `secret` を必ず付ける。合言葉が違えば何もしない。

| action | 送るもの | 返すもの | 内容 |
|---|---|---|---|
| `uploadPhoto` | kind, ownerId, clientKey, staff, dataBase64 | fileId | 保存する。**同じ ownerId・clientKey が既にあれば、新しく作らずに既存の fileId を返す** |
| `listPhotos` | kind, ownerId | `[{fileId, createdAt}]` | 削除されていない写真を古い順に返す |
| `getPhoto` | fileId | dataBase64 | 写真を返す。公開URLは作らない |
| `deletePhoto` | fileId | — | 台帳の deleted を TRUE にし、Driveのファイルをゴミ箱へ。ゴミ箱なら30日間は戻せる |

- 写真は端末で縮小済み（長い辺800px、画質72%、1枚約100KB）。ここでは縮小しない
- 複数の人が同時に写真を送ったときに台帳が壊れないよう、書き込み時は `LockService` で順番待ちさせる

## 4. アプリ側（今の版）の動き

### 4-1. 写真を保存するとき（入力・編集画面）

1. 「保存」で、まず**今まで通り案件をシートに保存する**（写真の送信を待たない）
2. そのあと、新しく追加した写真を1枚ずつ写真用GASへ送る。画面には「写真を送信中 2/5」と出す
3. 送れた写真は、返ってきた fileId で端末にも保存する（4-4）。次からは通信しない
4. **送れなかった写真は「未送信」として端末に残す。** 次にアプリを開いたとき、または詳細画面の「再送信」ボタンで送り直す。未送信が残っていることは画面に表示する
5. 編集画面で×を押して消した写真は、`deletePhoto` を送る

案件の保存と写真の送信を分けるのは、写真が送れなかったせいで案件の保存まで失敗するのを避けるため。

### 4-2. 写真を見るとき（詳細画面）

1. 端末に保存してある写真と未送信の写真を、**すぐに表示する**
2. 裏で `listPhotos` を呼んで、写真の一覧を最新にする
3. 端末にない写真は、枠だけ先に出して、`getPhoto` で取りに行く（同時に3枚まで）。届いたものから表示し、端末に保存する
4. 案件一覧の読み込みでは写真を取りに行かない（一覧の速さは今と変わらない）

### 4-3. 二重登録を防ぐ仕組み

電波が悪いと「送れたのに、アプリには失敗と見える」ことがある。そのまま送り直すと同じ写真が2枚になる。

そこで、写真の中身から指紋（`clientKey`。SHA-256）を作って一緒に送る。写真用GASは、同じ案件で同じ指紋の写真が既にあれば、新しく作らずに既存の fileId を返す。これで**何回送り直しても1枚にしかならない**。移行（5章）の送り直しにも同じ仕組みを使う。

### 4-4. 端末での写真の保存先

- 今の `localStorage` は容量が約5MBしかない。写真だと30〜40枚ほどで一杯になる（今も「容量不足」のメッセージが出る作り）
- そこで写真は **IndexedDB**（ブラウザの大きめの保存場所）に、fileId をキーにして保存する
- 保存した写真が増えすぎたら、古く見たものから消す（上限の目安は300枚）。消しても、また開けばDriveから取ってくる

### 4-5. 接続先の設定

- `src/js/config.js` に `PHOTO_GAS_URL` と `PHOTO_SECRET` を足す
- **注意**：本番のHTMLは誰でも開けるので、合言葉もHTMLを見れば分かる。今の `GAS_URL`（合言葉なし）よりは安全だけど、完全な鍵ではない。これは承知の上で進める（9月の設計と同じ考え方）
- ブラウザからGASにPOSTするときは、`Content-Type: text/plain` で送る。`application/json` にすると、事前確認の通信が発生してGASが受け付けない。テストはcurlで行ったので、ブラウザからの送信は未確認。最初に確かめる

### 4-6. 直すファイル

| ファイル | 変更 |
|---|---|
| `src/js/config.js` | 接続先と合言葉を追加 |
| `src/js/photos.js` | 送信、取得、未送信の管理、IndexedDB、移行 |
| `src/js/api.js` | 写真用GASとの通信（今の `gasCall` とは別の関数にする） |
| `src/js/ui.js` | 詳細画面・編集画面の写真部分、送信中・未送信の表示 |
| `src/js/main.js` | 起動時に未送信の再送と移行を呼ぶ |

## 5. 今ある写真の引っ越し

今の写真は、撮った人の端末の `localStorage`（`proj_photos_{案件id}`）にしかない。

1. 新しい版を開いた端末は、起動後に `proj_photos_*` を探す
2. 見つかった写真を、4-3の指紋付きで1枚ずつ写真用GASへ送る
3. その案件の写真が**全部**送れたら、`localStorage` の元データを消す。1枚でも失敗したら消さずに、次の起動で続きから送る
4. 画面には「前の写真を移しています 3/12」と出す

**運用上のお願い**（社長・新井さん・小林さん全員）：
- 新しい版を出したら、写真を撮ったことのある**すべての端末（スマホもパソコンも）で一度アプリを開く**。電波の良い場所で、表示が終わるまで閉じない
- **それまでブラウザの履歴やデータを消さない**。消すと、その端末の写真は失われる

## 9. 気になる点

- **写真1枚ごとにGASの遅さがかかる**（1.5〜40秒）。同時に3枚まで取りに行くこと、端末に保存して2回目からは通信しないことで、見る側の待ちを減らす。一覧の読み込みには影響しない
- **会社用アカウントに入れなくなると写真も見られなくなる**。予備の電話（社長）、バックアップコード（会社で保管）、再設定用メール（会社のメール）で、入る手段を複数にしておく
- 無料のGmailは15GB。年に約200MBの試算なので当面は問題ない。Driveの使用量は年1回確認する
